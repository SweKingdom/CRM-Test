# Solution design — Zephyr CRM, local edition

Scope of this version: FT-108 Local stack, seeds and quality gate (US-127…US-132). Domain features will extend it. The repository is greenfield (only docs and `.gitignore`).

## Architecture overview
Headless .NET API (`src/backend/Zephyr.Api`) + web frontend (`src/frontend`, framework not yet confirmed) + PostgreSQL 16, all on one machine via Docker Compose. Keycloak replaces Entra (OIDC code + PKCE); Mailpit catches SMTP. One OCI image per app, configured only by env vars, logs to stdout, `/health`. No cloud SDK, no paid service.

## Data model (baseline)
Conventions on every table: `id uuid`, `created_at`, `updated_at`, `created_by`, `updated_by`, `deleted_at`, `custom jsonb`. Money: `amount numeric(18,2)`, `currency char(3)`, `amount_sek`, `rate_date`. Tables: `external_id` (unique system+entity_type+value), `audit_log` (append-only). Extensions: `pg_trgm`, `unaccent`. Reference tables (stages, call outcomes, time types, countries, currencies, MEDDPICC) are seeded by `Seed/*.sql` with `ON CONFLICT DO NOTHING`.

## API inventory

| Route | Notes |
|---|---|
| GET /health | Anonymous; 200 when API and DB reachable, else 503 |
| GET /api/v1/exchange-rates, PUT /api/v1/exchange-rates/{currency}/{yyyy-MM} | Rates; PUT admin only (US-134) |
| PUT /api/v1/{plural}/by-external-id/{system}/{value} | Idempotent upsert, 201/200 (US-135) |
| DELETE /api/v1/{plural}/{id} | Soft delete, 204 (US-135) |

Conventions (US-133): base `/api/v1`, camelCase, keyset cursor paging (default 50, max 200, over-limit is 400), `filter[field][op]`, `sort=-updatedAt`, strong ETag on reads, PATCH is merge-patch with `If-Match` (428 missing, 412 stale), errors are RFC 9457 `application/problem+json` with `errors[]` of `{field, code, message}`. Money JSON is `{amount, currency, amountSEK, rateDate}` with string amounts. The OpenAPI 3.1 file `docs/api/openapi.yaml` is generated by `tools/openapi-from-metadata/generate.mjs`, linted by Spectral 6.15.0, drift-checked and oasdiff-checked in `scripts/check` and CI (US-136).

## Security model
Sign-in via Keycloak issuer+subject; Zephyr stores no passwords. Secrets only in gitignored `.env`; realm files are templates with placeholders; ports bound to 127.0.0.1; CI has read-only permissions and no secrets.

## Key decisions

| Decision | Reason | Alternatives |
|---|---|---|
| EF Core migrations, applied at API start | Default for .NET, has down migrations | DbUp, Flyway |
| Seeds as SQL run by `scripts/seed.mjs` | Idempotent via ON CONFLICT, works from host and CI | EF HasData, app-startup seeding |
| Realm templates rendered by script | Keycloak import does not substitute env into JSON reliably; keeps passwords out of git | Committed passwords, Admin API calls after start |
| Deterministic volume seed in SQL (`setseed`, md5-derived UUIDs) | Repeatable, fast set-based load | App-level generator |
| `scripts/check` runs all steps, SKIPs inapplicable ones visibly | Gate usable before all stories exist | Fail on missing parts |
| Keyset cursor paging (US-133) | Stable and fast over ~56,000 rows | Offset paging |
| ETag from id + `updated_at`, compared in the UPDATE's WHERE clause (US-133) | Race-free, no extra column | xmin, version column |
| Over-limit `limit` returns 400, not silent cap | Explicit for integrators | Silent cap |
| Money stamped at write time using the rate of the record's business month; half-up rounding (US-134) | Totals stay stable when rates change | Recompute on read |
| Upsert via `INSERT … ON CONFLICT DO NOTHING` on `external_id`, then update (US-135) | Race-safe, single row | Select-then-insert |
| OpenAPI generated from field metadata, committed, drift-checked (US-136) | Docs cannot diverge | Code-first reflection, hand-written |

## Identity, sessions and API tokens (FT-111)

**Modules:** `src/backend/Zephyr.Api/Auth/AuthModule.cs` (OIDC + cookie, matching, bootstrap, session rules), `Auth/UsersEndpoints.cs` (US-141), `Auth/ApiTokens.cs` (US-142). Tables `app_user` (nullable issuer/subject until linked, roles text[], active) and `api_token` (SHA-256 hash). Auth tests under `Zephyr.Api.Tests/Auth`.

**API:** `/auth/login|logout|me|denied`, `PATCH /api/v1/users/{id}` (Admin, merge-patch `active`, If-Match), `POST|GET|DELETE /api/v1/me/tokens`.

**Config:** `ZEPHYR_AUTH__PROVIDERS__n__*` (Name, Authority, ClientId, ClientSecret, EmailTrusted), `ZEPHYR_BOOTSTRAP_ADMIN_ISSUER/SUBJECT`, `SESSION_IDLE_SECONDS` (14400), `SESSION_ABSOLUTE_SECONDS` (43200), `USER_STATUS_RECHECK_SECONDS` (300).

**Security:** no passwords stored; no self sign-up; email linking only if provider EmailTrusted and `email_verified`; open-redirect check on returnUrl; cookie HttpOnly/SameSite=Lax; tokens cannot create tokens; token plaintext shown once and never logged; revocation checked in DB on every request; deactivation enforced via 5-minute cached status shared by cookie and token auth; all time via `TimeProvider` (fake in tests).

**Decisions**
- Pre-provisioned users, linked on first sign-in · satisfies no-self-signup and email linking · alternative: JIT creation (rejected).
- Absolute session via ticket `issued_utc` + sliding idle cookie · plain ASP.NET Core, no session store · alternative: server-side session table.
- Unsalted SHA-256 for 256-bit random tokens · indexable lookup, no brute-force risk · alternative: HMAC with pepper if security review requires.
- One OIDC scheme per configured provider · second realm by config only · alternative: single scheme with dynamic authority.
- 401 for deactivated user's requests · standard for failed auth.

**Risks**
- SHA-256 not yet approved (low/low): hash function isolated in one method.
- Status cache is per-instance (low/low): single instance locally; bound is 5 min regardless.
- Role names assumed from personas (medium/low): confirm with PO.

## Roles and permission sets (FT-112)

**Modules:** `Zephyr.Api/Permissions/` — `permission-matrix.csv` (embedded, single source), `PermissionSeeder.cs`, `PermissionService.cs` (scope map + SQL predicates), `PermissionFilter.cs` (route metadata), `PermissionEndpoints.cs`, `Approvers.cs`. Docs: `docs/permissions.md`. Tests under `Zephyr.Api.Tests/Permissions`; Playwright e2e for UI routes.

**Data model:** `role(key,label)`, `role_permission(role_key,entity,action,scope)`, `app_user.manager_id`, `country_code`, `business_unit`, `project_approver(project_id,user_id)`, `approval_delegation(delegator_id,delegate_id,from_date,to_date,revoked_at)`. `app_user.roles` (text[]) keeps role keys; widest scope across roles wins.

**API:** `GET /api/v1/me/permissions`; `PUT|DELETE /api/v1/projects/{id}/approvers/{userId}`; `POST /api/v1/delegations`, `DELETE /api/v1/delegations/{id}`.

**Security:** default deny (every API endpoint must declare entity+action; test enforces); read outside scope → 404, write on visible record without right → 403; scope predicates are parameterised SQL shared by lists, single reads and search; role change effective within the existing 5-min status cache; tokens inherit owner permissions; approvers read only their projects' time; self-approval blocked; delegations evaluated per request in UTC.

**Decisions**
- Matrix as embedded CSV seeded to tables · reviewable in PRs, DB stays in sync, testable · alternative: admin-editable matrix UI (out of scope).
- Team = same `manager_id` (no `team_id`) · one concept · alternative: team table.
- 404 for invisible records, 403 for denied actions · avoids existence leaks.
- One engine for list, single, search and UI endpoint · parity by construction.
- Backend permission tests use a test auth handler; Keycloak only in e2e · speed with real-IdP coverage.

**Risks**
- Matrix values need PO sign-off (medium/high): developer fills from proposal; PO approves `docs/permissions.md`.
- `country` scope vs business unit semantics unclear (medium/medium).
- Predicate drift between list and search (medium/high): single predicate builder + leak tests.
- Admin access to time/CRM content undecided (medium/medium).

## App shell, search, Account/Contact 360, performance (FT-113)

**Modules:** `Zephyr.Api/Search/SearchEndpoints.cs`, `Accounts/AccountEndpoints.cs`, `Contacts/ContactEndpoints.cs`; frontend `src/frontend/src/{shell,pages,lib}`; `tools/perf/`; docs `docs/perf/report.md`.

**Data model:** `search_document(entity_type, entity_id, title, subtitle, text, tsv, owner_id, account_id, country_code, business_unit, updated_at)` with GIN(tsv), GIN trigram(text), maintained by DB triggers; `account` and `contact` tables per US-149 (contracting country limited to six via `country.is_contracting`).

**API:** `GET /api/v1/search?q=&types=&limit=` → `{items,fallback}`; accounts and contacts CRUD + `/overview` (sections keyset-paged).

**Security:** search and overview use the shared scope predicate builder from FT-112 inside SQL; invisible → 404; default-deny entity+action declarations; no tokens in browser storage.

**Decisions**
- Search index kept by triggers in-transaction · no lag, no job · alternatives: periodic job, generated column per table.
- `simple` FTS config + `unaccent` wrapper + prefix tsquery, trigram fallback when <5 hits · multilingual names, typo tolerance · alternative: language stemmers.
- Frontend React + TypeScript + Vite, plain CSS, Playwright + axe (assumption, was open) · free, common, full control of contrast/keyboard · alternatives: Blazor, Vue, UI kits.
- Overview as parallel section queries with `available:false` for not-yet-built sections · independent delivery, fast first paint · alternative: one big join.
- Perf: k6 (container) + Playwright screen timings, run by hand · free, p95 thresholds built in · alternative: autocannon.

**Risks**
- Search predicate drift vs lists (medium/high): single builder + leak tests.
- 2 s Account 360 for big accounts (low/medium): first page 10, capped counts, indexes on child FKs.
- Local perf is not cloud proof (certain/low): caveat in report.
- Consent enum and account delete rules assumed (medium/low): confirm with PO.
