# BUILD.md

How Zephyr was built, feature by feature, so an outsider can rebuild it. Each `##` section covers one merged feature and has the six parts defined in `build/prompts/feature-section.md`. A feature's section is added in that feature's pull request and reviewed by a second developer. To rebuild the environment, start with the "Run Zephyr locally" section of `README.md`.

## FT-108 — Local platform foundations (US-127, US-128, US-129, US-130)

### Goal
One `docker compose up` gives a developer the whole system on a laptop at zero cost: database, API, web app, Keycloak sign-in with one test user per role, and a mail catcher. The database has a shared schema baseline and the reference data and demo accounts needed to use the system straight away.

### Prompts used
The story texts of US-127 to US-130 (acceptance criteria and technical specification) were the prompts for the developer agent. QA and architect review feedback was given back as rework comments on each story. No separate prompt transcript is recorded in the repository.

### Decisions
- Plain Compose, all ports on `127.0.0.1`, settings only from `.env` (generated by `scripts/setup-env.mjs`, never committed) · works with Docker, Podman and Rancher Desktop.
- Keycloak realm templates are rendered by script into a gitignored folder · Keycloak import does not substitute environment variables, and passwords stay out of git.
- A second realm `zephyr-b` with its own issuer · lets the issuer be switched by configuration.
- EF Core migrations are the only schema mechanism, applied when the API starts; `Seed/*.sql` is data only.
- Seeds: reference rows use `ON CONFLICT DO UPDATE`, demo rows use `DO NOTHING` · reference changes reach existing databases, user edits are never overwritten.
- Test database per run (`zephyr_test_<guid>`) reset with Respawn; `audit_log` is ignored by the reset because it is append-only.
- Pinned images: `postgres:16`, `quay.io/keycloak/keycloak:26.0.7`, `axllent/mailpit:v1.21`, .NET 8 for the API. The pins are unverified until the first real `docker compose up`.
- The local edition defers the cloud decisions ADR-001 and ADR-002; see `docs/adr/ADR-013-local-edition.md`.

- Tooling: `package.json`, `.editorconfig`, `scripts/lint.mjs`.

### How to verify
```sh
npm run typecheck && npm run lint && npm test && npm run build
```

Database tests need PostgreSQL (`ZEPHYR_TEST_DB`) and are skipped without it; CI sets `ZEPHYR_REQUIRE_DB=1`. For the running stack, follow `README.md` ("Run Zephyr locally"): `docker compose ps` shows every service healthy, `curl http://localhost:8080/health` returns `{"status":"Healthy"}`, and `salesperson@example.com` can sign in at <http://localhost:8180/realms/zephyr/account>.
